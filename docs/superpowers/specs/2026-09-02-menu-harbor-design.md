# MenuHarbor 产品与技术设计

日期：2026-09-02  
状态：已批准（用户明确授权自主决策并要求连续交付 MVP）

## 1. 产品定义

MenuHarbor 是一款 macOS 菜单栏工具。它把容易被刘海或应用菜单挤掉的状态图标收进一个可折叠的“港湾”，并在刘海下方提供可搜索、可点击的图标架。

首版只解决一个高频问题：**图标再多，也能在不切换应用、不寻找隐藏位置的情况下快速找到并使用。** 它不扩展成剪贴板、播放器、文件暂存等“刘海万能岛”，避免增加新的视觉噪声。

## 2. 目标用户与成功标准

目标用户是使用带刘海 MacBook、常驻 8 个以上菜单栏工具的重度用户，也覆盖小屏或应用菜单很长的场景。

成功标准：

1. 用户完成一次 `⌘` 拖拽整理后，能一键折叠隐藏区。
2. 隐藏图标能在刘海下方的图标架中被识别、搜索和点击。
3. 不授予增强权限时，基础折叠仍可工作；权限用途在请求前解释清楚。
4. 应用不出现在 Dock，不抢当前应用焦点，空闲时不持续高频扫描。
5. 退出或关闭管理功能后，图标可恢复到原生菜单栏。

## 3. 方案比较与决策

### 方案 A：只做分隔符折叠

通过一个可伸缩的 `NSStatusItem` 把其左侧项目推到屏幕外。优点是实现小、稳定、基础功能几乎不需要权限；缺点是隐藏后只能整体展开，无法集中浏览或搜索，仍会受到刘海宽度限制。

### 方案 B：完全复制菜单栏控件

读取每个状态项并在自有面板中重建交互。体验看似最理想，但 macOS 没有公开 API 提供第三方状态项的语义和菜单，无法可靠复制；强行依赖私有接口会让系统升级风险、权限和签名风险都过高。

### 方案 C：折叠核心 + 可选增强图标架（采用）

以方案 A 作为永远可用的核心；用户允许屏幕录制和辅助功能后，缓存隐藏图标的图像，在刘海下方展示。点击图像时短暂把原状态项移回可交互区域并发送原生点击，然后恢复隐藏状态。

它兼顾了可靠退路和产品体验。图标架是原控件的入口，不伪装成真正的控件克隆；权限被拒绝、截图失败或系统行为变化时，用户仍可通过“展开到菜单栏”完成任务。

## 4. MVP 范围

### 4.1 菜单栏结构

- 主按钮：始终靠近系统区，左键打开图标架；右键打开简洁操作菜单。
- 隐藏分隔符：用户按住 `⌘` 拖动其他图标到其左侧，形成隐藏区。
- 折叠状态：分隔符扩展到足够宽，把隐藏区推离屏幕；展开状态恢复到窄宽度。
- 防误操作：退出前先展开；偏好中提供“立即恢复全部”。

### 4.2 Harbor Shelf

- 非激活浮层位于当前屏幕菜单栏下方，优先锚定主按钮；不会被刘海遮挡。
- 顶部包含状态、搜索和“展开全部”操作；下方以横向图标带展示隐藏项。
- 每个图标有名称、悬停提示和键盘焦点；支持左右方向键、Return 和 Escape。
- 点击增强图标失败时，不静默：关闭图标架并原生展开菜单栏，同时显示短暂提示。

### 4.3 自动化与偏好

- 自动收起：关闭 / 5 秒 / 10 秒 / 30 秒，默认 10 秒。
- 登录启动：使用 `SMAppService.mainApp`。
- 菜单栏按钮样式：港湾符号或低调圆点；默认港湾符号。
- 全局快捷键：默认 `⌃⌥H`，首版可开关，不做自定义录制器。
- 本地存储：仅 `UserDefaults`；不联网、不采集分析。

### 4.4 首次引导

单窗口三步：

1. 解释“分隔符如何工作”，基础模式无需增强权限。
2. 用静态菜单栏示意指导用户按住 `⌘` 拖动图标。
3. 可选开启屏幕录制（读取图标外观）和辅助功能（代替用户点击原图标），每项独立授权。

引导允许跳过，主界面始终能重新打开。

## 5. 视觉与交互系统

方向采用原生、紧凑、安静的 Swiss minimal，而不是高饱和“AI 工具”风格。

- 基础材质：`NSVisualEffectView` / SwiftUI material，跟随系统深浅色。
- 强调色：Harbor Teal（以系统 `teal` 为基准）；橙色只用于需要用户处理的权限提示。
- 字体：系统 San Francisco；数字或快捷键使用 monospaced digit，不下载字体。
- 圆角：浮层 16 pt、卡片 10 pt、胶囊控件全圆角。
- 密度：图标命中区不小于 36×36 pt，主要按钮不小于 44×28 pt；列表间距 8 pt。
- 动效：打开 160–200 ms 的轻微位移和透明度；尊重“减弱动态效果”。不做弹跳、呼吸灯或持续动画。
- 图标：只使用 SF Symbols 和自绘矢量，不使用 emoji。

## 6. 架构与边界

采用 Swift Package Manager 构建原生 SwiftUI/AppKit 菜单栏应用，最低 macOS 14。

```text
Sources/MenuHarbor/
  App/            生命周期、依赖装配、应用状态
  Domain/         设置、状态项描述、分区与纯状态机
  MenuBar/        两个 NSStatusItem、折叠控制、状态项扫描与点击代理
  UI/             图标架、设置、首次引导、共享视觉组件
  System/         权限、登录启动、快捷键、偏好存储
Tests/MenuHarborTests/
  Domain/         折叠状态、分区、过滤和计时规则
  System/         偏好编码与权限无关逻辑
```

边界规则：

- Domain 不导入 SwiftUI/AppKit，所有关键行为可单测。
- Window Server / CoreGraphics 的不稳定细节藏在 `MenuBarScanning` 和 `MenuBarInteracting` 协议后。
- UI 只依赖可观察的 `AppModel`，不直接调用私有符号。
- 私有 CGS 查询若不可用，扫描器回退到 `CGWindowListCopyWindowInfo`；基础折叠不依赖扫描器。

## 7. 数据流

```text
用户点主按钮
  → AppModel 请求扫描隐藏区
  → Scanner 返回状态项窗口元数据
  → SnapshotService 在已授权时返回图标图像
  → ShelfModel 过滤、排序并展示
  → 用户点某图标
  → Interactor 暂时展开并定位原状态项
  → 发送原生点击
  → AutoHideCoordinator 在菜单关闭后恢复折叠
```

扫描在打开图标架或应用列表变化时触发，不做逐帧监听；图像缓存以窗口 ID 和尺寸为键，在状态项变化、屏幕变化或显式刷新时失效。

## 8. 错误处理与恢复

- 没有屏幕录制权限：图标架显示应用名称和通用图标，同时保留“展开全部”。
- 没有辅助功能权限：图标仍可浏览，点击改为展开原生菜单栏并引导用户手动点击。
- 状态项消失或窗口 ID 变化：忽略该项、刷新一次，不阻塞其余项目。
- 多显示器/全屏空间切换：关闭浮层、重新计算主屏和安全区域。
- 系统自动隐藏菜单栏：不尝试显示过期截图，改为基础展开模式并说明限制。
- 应用崩溃或被强制退出：系统会移除 MenuHarbor 的分隔状态项，其他应用的状态项自然恢复。

## 9. 测试与验收

自动化测试覆盖：

- 分隔符左右的状态项分区与稳定排序。
- 搜索对名称、进程名大小写不敏感。
- 自动收起策略和用户交互续期。
- 权限组合对应的能力降级文案与动作。
- 偏好默认值、持久化和非法值回退。

手工验收覆盖：

- 带刘海主屏与外接屏；浅色、深色；“减弱动态效果”。
- 10 个以上第三方状态项，折叠、展开、搜索、左右键与点击。
- 两项权限的允许、拒绝、撤销；系统自动隐藏菜单栏。
- 登录启动切换、应用退出恢复、睡眠唤醒与切换 Space。

## 10. 明确不做

- 不重建第三方菜单内容，不承诺 App Store 上架。
- 不做云同步、账号、统计、自动更新或商业支付。
- 不做每个应用的规则引擎、多个配置档或按场景自动切换。
- 不修改系统菜单栏间距或外观，不替代 Control Center。

这些能力只有在核心折叠与图标架被真实使用验证后再考虑。
